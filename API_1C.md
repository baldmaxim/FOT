# Инструкция: подключение из 1С к FOT Data API

Read-only публичный API для внешних систем. Управление ключами и whitelist таблиц/полей — через админ-вкладку «API-доступ» в FOT.

---

## 1. Базовый URL

- Прод (HTTPS): `https://fot.su10.ru/external/v1`
- Прод (HTTP): `http://fot.su10.ru/external/v1`

## 2. Аутентификация

В каждый запрос (кроме `/health`) добавить HTTP-заголовок:

```
Authorization: Bearer fot_<prefix>_<secret>
```

Полный токен выдаётся **один раз** при создании ключа и имеет вид `fot_<16 hex>_<48 hex>`. Если токен потерян — нужно создать новый ключ.

## 3. Доступные endpoints (только GET, read-only)

| Метод | URL | Назначение |
|---|---|---|
| GET | `/external/v1/health` | Проверка доступности (без авторизации) |
| GET | `/external/v1/tables` | Список таблиц, разрешённых ключу |
| GET | `/external/v1/tables/{name}/schema` | Список полей таблицы |
| GET | `/external/v1/tables/{name}` | Чтение строк таблицы |

## 4. Параметры query-string для чтения данных

- `limit` — 1..1000, по умолчанию 100
- `offset` — пропустить N строк, по умолчанию 0
- `order=поле.asc` или `order=поле.desc`
- Фильтры: `eq.поле=значение`, `neq.`, `gt.`, `gte.`, `lt.`, `lte.`, `like.`, `ilike.`, `in.поле=v1,v2,v3`

Поля в фильтрах должны быть в whitelist ключа, иначе 400.

## 5. Формат ответа

```json
{
  "data": [ { ... }, { ... } ],
  "limit": 100,
  "offset": 0
}
```

## 6. Лимиты и ошибки

- Rate limit per-key — настраивается на ключе (default 60 req/min). При превышении — `429 Too Many Requests`.
- `401` — нет/неверный/отозванный/просроченный ключ.
- `404` — таблица недоступна этому ключу.
- `400` — поле не в whitelist, кривые параметры.

## 7. Документация Swagger

`https://fot.su10.ru/external/v1/docs` — интерактивная документация со всеми endpoints.

## Готовый код для 1С

### Универсальная функция запроса

```bsl
// Возвращает структуру { Код, Тело } — Тело уже распаршен из JSON.
Функция ВыполнитьЗапросFOT(Путь, ПараметрыЗапроса = Неопределено) Экспорт

    Хост      = "fot.su10.ru";
    Порт      = 443;             // стандартный HTTPS-порт
    ApiKey    = "fot_XXXXXXXXXXXXXXXX_YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY"; // подставить выданный токен

    SSL = Новый ЗащищённоеСоединениеOpenSSL();
    Соединение = Новый HTTPСоединение(Хост, Порт, , , , 30, SSL);

    ПолныйПуть = "/external/v1/" + Путь;
    Если ПараметрыЗапроса <> Неопределено И ПараметрыЗапроса.Количество() > 0 Тогда
        ЧастиQS = Новый Массив;
        Для Каждого КЗ Из ПараметрыЗапроса Цикл
            ЧастиQS.Добавить(КЗ.Ключ + "=" + Строка(КЗ.Значение));
        КонецЦикла;
        ПолныйПуть = ПолныйПуть + "?" + СтрСоединить(ЧастиQS, "&");
    КонецЕсли;

    Заголовки = Новый Соответствие;
    Заголовки.Вставить("Authorization", "Bearer " + ApiKey);
    Заголовки.Вставить("Accept", "application/json");

    Запрос = Новый HTTPЗапрос(ПолныйПуть, Заголовки);
    Ответ  = Соединение.Получить(Запрос);

    Результат = Новый Структура("Код, Тело");
    Результат.Код  = Ответ.КодСостояния;
    ТекстОтвета    = Ответ.ПолучитьТелоКакСтроку("UTF-8");

    Если ПустаяСтрока(ТекстОтвета) Тогда
        Результат.Тело = Неопределено;
    Иначе
        Чтение = Новый ЧтениеJSON;
        Чтение.УстановитьСтроку(ТекстОтвета);
        Результат.Тело = ПрочитатьJSON(Чтение, Истина);
    КонецЕсли;

    Возврат Результат;

КонецФункции
```

### Примеры использования

**Список доступных таблиц:**

```bsl
Ответ = ВыполнитьЗапросFOT("tables");
Если Ответ.Код = 200 Тогда

    КонецЦикла;
КонецЕсли;
```

**Прочитать первые 50 сотрудников отдела 5 с зарплатой ≥ 50000:**

```bsl

Параметры.Вставить("offset",       0);

Параметры.Вставить("eq.department_id", 5);

```

**Постраничная выгрузка всей таблицы:**

```bsl
Смещение = 0;

Пока Истина Цикл

    Если Ответ.Код <> 200 Или Ответ.Тело["data"].Количество() = 0 Тогда
        Прервать;
    КонецЕсли;

    Смещение = Смещение + Размер;
КонецЦикла;
```

### Если 1С на старом релизе (без OpenSSL по умолчанию)

Использовать HTTP без шифрования: `Хост = "fot.su10.ru"`, `Порт = 80`, без `ЗащищённоеСоединениеOpenSSL`. Но токен будет летать в открытом виде — рекомендуется только для тестов.

## Расчётный табель отдела (JSON)

Помимо «сырых» таблиц `/external/v1/*` есть **расчётный** эндпоинт: он отдаёт уже
собранный табель отдела со всеми корректировками (тот же расчёт, что в выгрузке
«Единый 1С»), а не сырые СКУД-события. Это отдельный путь на Node — `/api/public/v1`
(не `/external/v1`), но авторизация тем же data-api токеном.

- **URL:** `GET https://fot.su10.ru/api/public/v1/timesheet`
- **Авторизация:** `Authorization: Bearer fot_<prefix>_<secret>` (как обычно).
- **Требование:** ключу должна быть открыта таблица `employees` (вкладка «API-доступ» →
  ключ → «Таблицы»). Иначе `403`.

### Параметры query-string

| Параметр | Обязателен | Значение |
|---|---|---|
| `department_id` | да | UUID отдела/бригады. Несколько — через запятую. Поддерево НЕ раскрывается: подотделы перечисляйте явно. |
| `month` | да | Месяц `YYYY-MM`. |
| `half` | нет | `FULL` (по умолч.), `H1` (1–15), `H2` (16–конец). |
| `from`, `to` | нет | Произвольный диапазон `YYYY-MM-DD` внутри месяца (имеет приоритет над `half`). |

### Формат ответа

```json
{
  "period": { "month": "2026-06", "start": "2026-06-01", "end": "2026-06-30", "half": "FULL" },
  "departments": [
    {
      "id": "0e2c…uuid",
      "name": "бр. Иванова",
      "employees": [
        {
          "id": 123,
          "full_name": "Иванов Иван Иванович",
          "tab_number": "СУ10-000123",
          "sigur_employee_id": 4567,
          "position": "Маляр",
          "total_hours": 168,
          "days": {
            "2026-06-01": { "status": "work",    "hours": 8, "corrected": false, "hours_overridden": false },
            "2026-06-02": { "status": "vacation", "hours": 0, "corrected": true,  "hours_overridden": false }
          }
        }
      ]
    }
  ]
}
```

- `status` — машинный код дня: `work`, `vacation`, `dayoff`, `remote`, `unpaid`,
  `absent`, `sick`, `business_trip`, `manual`.
- `corrected` — день получен/изменён ручной корректировкой; `hours_overridden` —
  часы заданы вручную поверх СКУД.
- `total_hours` — сумма часов за период.

### Ошибки

`401` — нет/неверный токен. `403` — ключу не открыта `employees`. `400` — нет/кривые
`department_id`/`month`/период.

### Проверка

```bash
curl -H "Authorization: Bearer fot_..." \
  "https://fot.su10.ru/api/public/v1/timesheet?department_id=<uuid>&month=2026-06&half=FULL"
```

# Закрытые согласованные табели — регулярный обмен с 1С

Раздел выше (`/api/public/v1/timesheet`) считает табель **на лету** за произвольный
период. Он остаётся рабочим, но для регулярной загрузки в 1С не подходит: по нему
нельзя понять, изменились ли данные с прошлого раза.

Ниже — основной механизм обмена. Машиночитаемый контракт — `docs/openapi-1c.yaml`
в репозитории проекта.

## 1. Что выгружается

Единица обмена — **подача табеля** (`approval_id`): отдел за период либо
персональная подача руководителя «по людям».

**Закрытый согласованный табель — неизменяемый официальный снимок.** В момент
утверждения и при каждом повторном закрытии ФОТ сохраняет версию: состав, часы по
дням, итоги. API отдаёт табель только из сохранённой версии и никогда не
пересчитывает его на лету. Из этого следуют два правила:

- фоновый пересчёт СКУД **не меняет** уже закрытый табель;
- чтобы правки попали в 1С, табель в ФОТ открывают, правят и закрывают заново.

## 2. Состояния

| Состояние | Что значит |
|---|---|
| `not_exported` | Версия ещё не подтверждена — нужно забрать |
| `stale` | Принята более ранняя редакция, появилась новая — нужно забрать |
| `exported` | Последняя редакция принята, делать нечего |

Фильтр `needs_export=true` = `not_exported` + `stale`.

## 3. Жизненный цикл

| Событие в ФОТ | Что происходит внутри | Что видит 1С |
|---|---|---|
| Табель согласован | Создаётся версия 1 | `not_exported` |
| 1С загрузила и подтвердила | Записан ACK версии 1 | `exported` |
| Табель открыт для правок | Ставится `unlocked_at` | Пропадает из списка; выгрузка и ACK дают `409 TIMESHEET_UNLOCKED` |
| Внесены правки | Сохранённая версия 1 не меняется | Незакрытые правки недоступны |
| Закрыт **без** фактических изменений | Хэш совпал, новая редакция не создаётся | Остаётся `exported` |
| Закрыт **с** изменениями | Создаётся версия 2 | `stale`, попадает в `needs_export=true` |
| Администратор поправил закрытый табель напрямую | Версия помечается на пересборку, затем формируется заново | Табель временно не выдаётся (`TIMESHEET_REBUILD_PENDING`), потом — как при обычном закрытии |
| 1С загрузила версию 2 и подтвердила | Записан ACK версии 2 | Снова `exported` |

## 4. Сопоставление сотрудников — реквизит `ID_FOT`

В ФОТ есть **полные однофамильцы** (57 групп, 114 человек), поэтому сопоставление
по ФИО недопустимо.

1. В справочнике «Сотрудники» 1С завести реквизит **`ID_FOT`** — целое число,
   уникальный индекс, доступен для поиска.
2. Один раз выполнить первичное сопоставление: выгрузить любой табель, сверить
   сотрудников по ФИО + подразделению и проставить `ID_FOT` = `identity.employee_id`.
   Спорные случаи (однофамильцы) развести вручную — их единицы.
3. Дальше сопоставление **только по `ID_FOT`**.

Остальные поля блока `identity`:
- `sigur_employee_id` — код в СКУД, резервный, для сверки;
- `tab_number` — **не ключ**: заполнен примерно у каждого восьмого и не уникален;
- `full_name` — только для отображения.

## 5. Какие строки переносить в документ

Ответ содержит **весь согласованный состав** — ровно тот, что был в закрытом табеле.
У каждого сотрудника есть флаг `zero_activity`:

- `zero_activity: false` — **переносить в документ**;
- `zero_activity: true` — за период нет ни одного реального сигнала (ни проходов,
  ни корректировок, ни объектной активности); такие строки в документ не переносятся.

Это соответствует прежнему правилу «не проходящие по СКУД не попадают в 1С».
Фильтра на стороне API нет намеренно: иначе `content_hash` и `employees_count`
не соответствовали бы фактически полученному телу.

## 6. Что должно быть настроено у ключа

Настраивает администратор ФОТ во вкладке «API-доступ», разработчику 1С делать ничего
не нужно — но если методы отвечают `403`, причина почти всегда здесь:

| Что | Где включается | Без него |
|---|---|---|
| Доступ к таблице `employees` | ключ → «Доступы» → отметить `employees` | `403` на всех методах табелей |
| Право подтверждать выгрузку | ключ → «Доступы» → «Разрешить подтверждение выгрузки табелей (POST /ack)» | `403` на подтверждении: табель заберётся, но останется в очереди навсегда |

В списке ключей колонка «Подтверждение 1С» показывает, включено ли право.

## 7. Порядок обмена

### Шаг 1. Узнать, что забирать

```
GET /api/public/v1/timesheets?month=2026-08&needs_export=true&limit=100
```

```json
{
  "period": { "month": "2026-08", "start": "2026-08-01", "end": "2026-08-15" },
  "data": [
    {
      "approval_id": 855,
      "scope": {
        "kind": "department",
        "department_id": "0e2c9f3a-1b4d-4c8e-9a10-2f3b4c5d6e7f",
        "department_name": "бр. Иванова",
        "manager_employee_id": null
      },
      "start_date": "2026-08-01",
      "end_date": "2026-08-15",
      "version_available": true,
      "revision": 2,
      "content_hash": "d41d8cd98f00b204e9800998ecf8427e",
      "employees_count": 28,
      "total_hours": 3248.5,
      "state": "stale",
      "last_export": { "revision": 1, "acked_at": "2026-08-16T06:03:11.000Z", "document_ref": "ТАБ-000123" }
    }
  ],
  "meta": { "without_version": 0 },
  "next_cursor": null
}
```

Метод лёгкий — табель не собирается, всё читается из сохранённых версий.
Опрашивать раз в минуту нормально.

**Пагинация — keyset.** Повторяйте запрос с `cursor` из `next_cursor`, пока тот не
станет `null`. Параметра `offset` нет: после подтверждения строки уходят из выборки
`needs_export=true`, и смещение пропускало бы сдвинувшиеся записи.

**`version_available: false`** — версия ещё не сформирована, выгрузить нельзя;
пропустить и повторить в следующем цикле. В норме таких нет; счётчик
`meta.without_version` показывает, сколько их в выборке.

**Табель, который сейчас пересобирается, в списке не появляется вообще** — ни в
`needs_export=true`, ни без фильтра. Так сделано намеренно: иначе можно было бы забрать
устаревшие часы. Пока идёт пересборка, `GET /timesheets/{id}` (в том числе с явным
`revision`) и `POST .../ack` отвечают `409 TIMESHEET_REBUILD_PENDING`. Через ~минуту
табель вернётся в список уже с новой редакцией.

### Шаг 3. Записать документ в 1С

Документ ищется по `approval_id` и **обновляется**, а не создаётся заново.
`approval_id` — постоянный идентификатор табеля, он не меняется между редакциями.

### Шаг 4. Подтвердить приём

```
POST /api/public/v1/timesheets/855/ack
Content-Type: application/json

{ "revision": 2, "document_ref": "ТАБ-000123" }
```

Отправляется **только после успешной записи документа**. После этого табель
переходит в `exported`, и в ФОТ у него появляется зелёная отметка.

`content_hash`, `employees_count` и `total_hours` сервер берёт из своей версии —
передавать их не нужно.

## 8. revision и content_hash

- `revision` — номер официальной редакции, растёт с каждой новой версией.
- `content_hash` — md5 содержимого версии.

Если `revision` вырос, а `content_hash` совпал с уже принятым, документ можно
не перепроводить. Но **ACK новой `revision` отправить обязательно** — иначе табель
навсегда останется в состоянии `stale` и будет вечно возвращаться в `needs_export`.

## 9. Ошибки и повторы

| Ответ | Причина | Что делать |
|---|---|---|
| `409 TIMESHEET_UNLOCKED` | Табель открыли для правок | Пропустить, повторить в следующем цикле |
| `409 TIMESHEET_REBUILD_PENDING` | Табель поправили, формируется новая редакция | Пропустить, повторить в следующем цикле (обычно ~минута) |
| `409 TIMESHEET_NOT_APPROVED` | Подача больше не утверждена | Пропустить |
| `409 VERSION_NOT_AVAILABLE` | Версия ещё не сформирована | Пропустить, повторить позже |
| `409 REVISION_MISMATCH` | Между загрузкой и ACK появилась новая редакция | Перечитать табель, обработать заново, подтвердить новую `revision` |
| `429` | Превышен лимит запросов ключа | Выдержать окно (по умолчанию 60 запросов в минуту) |
| `401` | Токен неверен, отозван или просрочен | Остановить обмен, обратиться к администратору ФОТ |
| `403` | Ключу не открыт доступ или не включено подтверждение | Обратиться к администратору ФОТ |

**Восстановление после сбоя связи.** ACK идемпотентен: повторное подтверждение той же
`revision` возвращает исходный `acked_at` и не создаёт вторую запись. Если связь
оборвалась после записи документа, но до ACK — просто повторите ACK. Если
неизвестно, прошёл ли ACK, повторите его: это безопасно.

## 11. Диагностика

- **Журнал обращений.** Каждый запрос к API пишется в ФОТ: админка → «API-доступ» →
  ключ → «Лог запросов». Видны время, метод, код ответа, длительность и текст ошибки.
- **Сверка содержимого.** Если возникло подозрение, что в 1С попали не те данные,
  сравните `content_hash` документа с `content_hash` текущей версии
  (`GET /timesheets/{approval_id}`). Разошлись — значит в 1С лежит старая редакция,
  её нужно перечитать и подтвердить заново.
- **Табель «завис» в `needs_export`.** Почти всегда причина одна: документ записан,
  а ACK не отправлен. Отправьте ACK текущей `revision`.
- **Состояние в интерфейсе ФОТ.** В разделах «Табели HR» и «Согласования» у каждого
  табеля показан статус выгрузки: выгружен / изменён после выгрузки / не выгружен,
  с датой подтверждения и номером документа.
