# Задание: проверить выгрузку закрытых табелей из ФОТ

Приёмка перед передачей контракта разработчикам 1С: воспроизвести тот же цикл,
который будет крутить 1С, и убедиться, что данные реально приходят.

Задание рассчитано на внешнего исполнителя или агента без доступа к репозиторию.

## Как подготовить рабочую папку

Создать папку **вне репозитория** (например `c:\tmp\fot-1c-check`) и положить туда:

| Файл | Откуда |
|---|---|
| `openapi-1c.yaml` | `docs/openapi-1c.yaml` |
| `Обмен_табелями_с_1С.md` | `docs/Обмен_табелями_с_1С.md` |
| `ЗАДАНИЕ.md` | этот файл |
| `.env` | создать вручную: `FOT_TOKEN=fot_<prefix>_<secret>` |

**`API_1C.md` целиком не класть.** Его первая половина описывает другой API —
«сырые» таблицы на базовом адресе `/external/v1`. Исполнитель прочитает первые
экраны, возьмёт оттуда базовый адрес и проверит не тот механизм, а отчёт при этом
будет выглядеть убедительно. Для того и собирается выдержка `Обмен_табелями_с_1С.md`.

**Ключ выдавать отдельный, без права подтверждения выгрузки.** В админке
«API-доступ» → создать ключ → доступ к таблице `employees`, галочку «Разрешить
подтверждение выгрузки табелей» **не ставить**. Тогда `POST .../ack` вернёт `403`
при любом раскладе, и прод-данные измениться не смогут. После проверки ключ отозвать.

---

## Доступ

```
Базовый адрес: https://fot.su10.ru/api/public/v1
Заголовок:     Authorization: Bearer <токен>
```

Токен лежит в `.env` рядом, переменная `FOT_TOKEN`.

**Читать токен из `.env` в переменную окружения. Не печатать его в вывод, в лог,
в отчёт и в чат.** Если нужно показать команду — писать `$FOT_TOKEN`.

## Правила

- **Только `GET`.** Метод `POST /timesheets/{approval_id}/ack` не вызывать.
  Это не чтение, а отметка «1С приняла эту редакцию»: после неё табель уходит из
  очереди `needs_export=true`, и настоящая 1С его пропустит. Часы и версии при этом
  не портятся — но очередь начинает врать. У выданного ключа права на этот метод
  нет, он вернёт `403`. Так и задумано, обходить не нужно.
- Лимит **60 запросов в минуту**. Между страницами делать паузу.
- Глубина запроса — **не более 3 месяцев** назад от текущей даты. Глубже `400`.
- Контракт всех методов — `openapi-1c.yaml`. Тот же контракт словами, с примерами
  и разбором состояний — `Обмен_табелями_с_1С.md`.

## Что сделать

**1. Забрать список того, что 1С должна выгрузить.**

```
GET /timesheets?needs_export=true
```

Пагинация — keyset, не offset. Повторять запрос, подставляя `cursor` из поля
`next_cursor` предыдущего ответа, пока `next_cursor` не станет `null`.
Собрать все страницы.

**2. Забрать несколько табелей целиком.**

```
GET /timesheets/{approval_id}
```

Взять 3–5 разных подач, желательно из разных отделов.

**3. Свести отчёт по чек-листу.**

## Чек-лист приёмки

Отчёт должен явно закрыть каждый пункт — «да/нет» и цифры.

1. Список отдаётся, код `200`, подачи есть. У каждой заполнены `approval_id`,
   `scope`, `start_date`, `end_date`, `revision`, `content_hash`, `state`.
2. Пагинация завершается: обход дошёл до `next_cursor: null`, а не зациклился.
   Указать, сколько всего подач собрано и за сколько страниц.
3. Поле `meta.without_version` — сколько подач без сформированной версии.
   Сверить с ожидаемым (уточнить у администратора ФОТ перед прогоном).
   Расхождение — повод разобраться, а не пройти мимо.
4. В выгрузке у каждого сотрудника есть `identity.employee_id`.
   **Это ключ сопоставления с 1С** (реквизит `ID_FOT`). Сопоставление по ФИО
   недопустимо: в базе есть полные тёзки — 57 групп, 114 человек. СНИЛС и дата
   рождения не заполнены, поэтому альтернативы нет.
5. По дням: у сотрудников заполнены значения по датам периода. У тех, кто не
   работал, стоит признак `zero_activity`.
6. Итоги сходятся: `employees_count` и `total_hours` из списка совпадают с тем,
   что лежит в теле выгрузки той же подачи.
7. Отделы различимы: у подач заполнены `department_id` и название отдела,
   то есть табели действительно разделены по отделам.
8. Версия заморожена: повторный `GET` той же подачи возвращает тот же
   `content_hash` и ту же `revision`.

## Формат отчёта

Кратко, по пунктам чек-листа. Плюс:

- один пример ответа `GET /timesheets` — одна строка списка целиком;
- один пример ответа `GET /timesheets/{id}` — **с обезличенными ФИО**
  (заменить на «Сотрудник 1», «Сотрудник 2»), остальные поля как есть;
- список замеченных расхождений и странностей, если были.

## Чего делать не нужно

- Не проверять запрет правок закрытого табеля администратором — это интерфейс ФОТ,
  а не API. Проверяется входом под админом: на согласованном периоде модалка дня
  открывается только на чтение с баннером «Период согласован — редактирование
  закрыто».
- Не проверять цикл «Открыть табель → правка → Закрыть»: он требует записи.
- Не пытаться менять данные любым способом.
